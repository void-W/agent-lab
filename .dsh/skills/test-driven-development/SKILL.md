# Test-Driven Development

## 核心纪律

没有先失败的测试，不写生产代码。实现已先写的，删除并从测试重来，不保留为参考。

## 循环

1. **RED**：只写一个描述期望行为的最小测试。
2. 运行，确认它因目标行为尚未实现而失败，而不是语法、环境或 fixture 错误。
3. **GREEN**：只写让该测试通过的最小实现。
4. 重跑该测试与相关回归。
5. **REFACTOR**：全绿后清理命名、结构和重复，并保持测试为绿。
6. 为下一个行为重复。

每组 RED/GREEN 保留可验证记录，并按工作流及时提交。

## 测试质量

- 一个测试验证一个行为，名称直接表达预期。
- 优先调用真实代码；mock 只隔离不可控外部依赖。
- 先理解依赖结构与副作用，再构造 test double。
- 测试公共行为，不断言 mock 自身，不加仅供测试的生产 API。
- 缺陷先写能稳定复现的测试。

## 外部系统

用 `httptest` 或本地替身，按真实协议回放；测试不联网、不要真实凭据。

## 完成检查

- 每个行为都有测试；
- 亲自观察过测试以预期原因失败；
- 只实现让测试通过所需的最小行为；
- 相关回归全绿；
- 未测试 mock 或自造测试专用生产接口。
